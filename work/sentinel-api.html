Sentinel API

A small API that tells you how a server is doing, and remembers when it was not.

The problem

A server rarely fails all at once. Memory creeps up, a disk fills, one process starts eating the CPU. I wanted a simple way to see that happening and to keep a record of each warning, without standing up a full monitoring stack.

What I built

Sentinel API is a FastAPI service that reports a machine's health and keeps a history of alerts.

  • Endpoints for overall health, CPU per core, memory and swap, disk, network and the top processes.
  • Alerts stored in SQLite through an async SQLAlchemy layer, filterable by severity, with a resolve action that records when each one was closed.
  • The code is split into a database module, models and schemas, and a CRUD layer, so storage can change without touching the endpoints.

What happened

I deployed it on Ubuntu behind an Nginx reverse proxy, with the ufw firewall and a Certbot TLS certificate. It is the project where I learned the most about persistence: designing the alert table, handling async sessions and keeping the API thin.
